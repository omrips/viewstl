# ViewSTL v2.00 — 2.0.0-rc.5

This GitHub release brings the native JavaScript/WebGL 2 plugin to the repository's
default `main` branch. It includes the current browser viewer and Node.js analysis
API, model exports, print checks, animation and VSB/VSJ playback persistence.

## Layout and legacy users

- v2 source is in `src/`; its complete distribution is in `build/`.
- The previous `master` branch and existing version tags remain unchanged.
- `legacy/v1/` preserves all 23 files from the pre-v2 GitHub tree, with a hash
  manifest and the original README. The separate local v1.14 snapshot is retained
  with its original provenance and 14-file manifest.
- Existing explicit `master` URLs continue to address the legacy files. The new
  default branch, new clones and this release's downloads provide v2.
- Integrations that depend on Three.js internals or older rendering fallbacks need
  migration. See [usage and compatibility](../v2-usage.md#existing-api-and-intentional-differences).

## Downloads

- `viewstl-2.0.0-rc.5.zip`: ready-to-host `build/`, README, license, notices and docs.
  Copy the whole build folder, including its worker, chunks and CAD assets.
- `omrips-viewstl-2.0.0-rc.5.tgz`: installable package for browser/Node applications.
  Run `npm install ./omrips-viewstl-2.0.0-rc.5.tgz` after downloading.
- `SHA256SUMS`: checksums for both download archives.

This is a GitHub prerelease. The npm registry package and dist-tags are unchanged;
the existing `2.0.0-rc.4` package has its previous `build/v2/` layout. The website,
Go URL relay and deployment infrastructure are not included in this repository update.

## Animation and scenes

The plugin exposes start, pause, resume, stop and state callbacks for elapsed-time
model animation. VSB/VSJ preserve definitions, phase, paused/running state, origin
and pivot. VSB carries the meshes; VSJ requires its referenced files. Ordinary
model exports and PNG capture a pose, not animation playback.

## Verification

The release layout is checked with unit tests, browser and Node TypeScript
consumers, both legacy manifests, actual browser harnesses and installation of
the packed distribution. Exact results and remaining coverage limits are recorded
in [verification](../v2-verification.md). Desktop Chromium checks do not establish
physical mobile, Safari or Firefox support.
